# Recording

Cornermark records a window or a display and stops on request. Record Project writes a project folder in the save folder. The folder holds `screen.mp4`, an H.264 video without the cursor in the picture, and `project.json`, which holds the pointer as a separate track and the edits to come. Record MP4 writes one dated `.mp4` file in the save folder, with the pointer in the picture and no project. Record GIF films the same way into a hidden `.<name>.gif.mp4` beside its GIF, then writes one dated `.gif` file and removes the hidden video.

## Sub-features

- `record-window` records one window by its window number, with `record?window=<id>`.
- `record-display` records a display, or an area of it, with `record?display=<id>` and `x`, `y`, `width`, `height` in global points with a bottom-left origin.
- `record-style` picks the result with `style=video`, `style=editing` or `style=gif`. A link without it records a project.
- `record-gif` makes an animated GIF: 15 fps, at most 960 pixels on the longest side, looping forever, with paused stretches left out. Convert to GIF on a video's Quick Access card or in History makes one beside a finished video. Conversion is harness-only, because it needs a click.
- `record-overlay` is Record Screen: the capture overlay chooses an area, a window or a display, and three start buttons pick the result: Record MP4, Record Project and Record GIF. It is harness-only.
- `record-sources` is the row of toggles in the recording panel: Microphone, System audio, Camera, Click highlights and Keystrokes. They write the same settings as the Audio, Camera and Recording panes; Click highlights writes `clicks.isVisible` and Keystrokes writes `keystrokes.isVisible`. Turning one on asks macOS for its permission when it has not asked yet (the microphone and camera prompts, and the Input Monitoring prompt through `CGRequestListenEventAccess`), once. Click highlights and Keystrokes share that one Input Monitoring request. While a microphone or camera prompt waits, the overlay leaves the screen and its toggle takes no clicks; the answer brings the overlay back with the same selection. The Input Monitoring request closes the overlay first, because macOS sends no answer and the permission applies only after Cornermark reopens. A refused source stays off and the panel says where to allow it. The log has `recording panel asks for access source=` and `recording panel access answer source= granted=`. A scripted instance reads every source as allowed and never asks. It is harness-only, because the overlay is.
- `record-options` is the options menu at the start of the recording panel's top row: quality, frame rate, countdown, show cursor, dim outside the area, and keeping notifications and desktop icons out. It writes the Recording pane's settings. It is harness-only.
- `record-help` is the help button beside Record Project. It opens a small window above the overlay that explains a project recording, with one Close button. It is harness-only.
- `record-stop` finishes the file with `record/stop`.
- `record-result` lists the finished recording in History, with its first frame as the picture and the video left in the save folder, and shows its Quick Access card.
- `record-settings` applies the Recording pane: frame rate, quality, resolution, largest size, and the cursor. It is harness-only, because a pane needs clicks.
- `record-controls` pauses, resumes, restarts and deletes a recording with `record/pause`, `record/resume`, `record/restart` and `record/discard`. `record/discard` logs `recording discarded seconds=` and leaves no file and no History entry. On the bar, the time is the stop button, and Delete asks for a second click. The on-screen control bar, the countdown and the dimming outside an area are harness-only, because a scripted instance never orders them in. The log shows `present window=Recording Controls visible=false`.
- `record-exclusion` keeps notifications and, when asked, desktop icons out of a display recording. The synthetic display carries test-owned fake windows (a banner, three desktop icons and a Finder window) that the same exclusion plan filters.
- `record-display-sleep` keeps the display awake while a recording runs. `pmset -g assertions` lists `PreventUserIdleDisplaySleep named: "Recording the screen"` for the instance's PID, and nothing after `record/stop`.
- `record-input` shows clicks and keystrokes. Record MP4 and Record GIF draw a ring at each click and a badge for key presses into the picture, when the Recording pane turns them on. Record Project draws nothing and keeps `events.clicks` and `events.keys` in `project.json`, with `edits.clicks` and `edits.keystrokes` copied from the settings. A live instance listens with a listen-only event tap and only with Input Monitoring allowed; it never asks for it. A scripted instance replays `InputScript.tour` and never creates a tap.
- `record-camera` shows the camera in a bubble while recording, when the Camera pane turns it on. Record MP4 and Record GIF draw it into the picture; Record Project writes `camera.mp4` beside `screen.mp4`, frame for frame on the same timeline, and keeps `source.camera` and `edits.camera` (shape, size, position, mirror, full-screen spans; the video editor can change all but the spans) in `project.json`. `record/camera` alone toggles full screen as a click on the bubble does; `shape`, `size`, `corner`, `mirror` and `full-screen` change the rest. A scripted instance draws a synthetic camera labelled SYNTHETIC CAMERA, logs `recording camera ... requests=0 sessions=0`, and never opens a real camera or asks for access. The bubble's window is harness-only, like the control bar: `CORNERMARK_CAMERA_FILM=<folder> swift run HarnessShell` films the real Camera pane and bubble view offscreen into `R11-onscreen.mp4`.
- `record-audio` records the microphone and what the Mac plays. Record Project keeps `mic.m4a` and `system.m4a` in the project folder, each AAC on the video's timeline and as long as it, and `project.json` names them in `source.microphone` and `source.systemAudio`. Record MP4 mixes them into the file's one AAC stereo track. Record GIF records no sound. Export mixes a project's tracks into the exported file. The control bar shows the microphone level and a No sound badge after 3 s under -80 dBFS. A scripted instance plays scripted sound through the same seams and never opens an audio device or asks for microphone access.
- `record-recovery` finishes a recording cut off by a crash at the next launch.
- `record-test-window` shows the instance's own synthetic window with `record/test-window`. A scripted instance has one, and no other instance does.
- `record-refusal` keeps a scripted instance from filming anything but its test window.

## How to get to it (user POV)

- Press `Ctrl+Option+Shift+9` in Cornermark Dev, choose the **Record** tile in the menu panel, or open `cornermark-dev://record-screen`. The overlay opens on the last area. Pick Area, Window or Fullscreen, then **Record MP4** (Return), **Record Project** (Shift-Return) or **Record GIF** (Option-Return). The toggles above them choose the microphone, system audio, camera, click highlights and keystrokes. The button at the start of the top row opens the quick recording options, and the help button beside Record Project explains what a project recording is. The same shortcut or the tile, now **Stop**, ends the recording.
- Open `cornermark-dev://record?window=<id>` or `cornermark-dev://record?display=<id>&x=<x>&y=<y>&width=<w>&height=<h>`, with `&style=video` for a plain video, then `cornermark-dev://record/stop`.
- `link.sh` refuses `record-screen`, because it shows the overlay over the screen. Run `swift run HarnessCapture` (section `recording overlay`) and `CORNERMARK_OVERLAY_FILM=<folder> swift run HarnessCapture`, which films the real overlay offscreen over a synthetic desktop into `R1.mp4` to `R5.mp4`.

## Driving it with link.sh

Preconditions:

- The baseline in [the map](./README.md) holds, and Cornermark Dev has Screen Recording permission (`screenPermission=true` in the launch line).
- `CORNERMARK_EVIDENCE_DIR` is a folder outside the repo, for the proof below.

- **Window.** Run `$V/link.sh record/test-window`. The output has `test window id=<n>` and `"onScreenWindowIDs":[<n>]`. Run `$V/watch.sh 14 &`, then `$V/link.sh record window=<n>`, wait, and `$V/link.sh record/stop`. The log has `recording started ... source=screen` and `recording finished ... frames= dropped= dropPercent=`. The recording is the folder `<root>/saved/Cornermark Recording <date>/`.
- **Display and area.** With no test window open, run `$V/link.sh record "display=1&x=0&y=0&width=960&height=540"`. The log must say `source=fixture`. The instance films its synthetic display, so the line proves the link, the area crop, and the writer, not live display capture.
- **GIF.** Add `&style=gif` to a display link. The `recording finished` line names the hidden `.gif.mp4` file, then `gif written file=... frames= size= seconds= bytes=` and `recording listed ... format=gif` follow. `<root>/saved/` holds one `.gif` file and nothing else. Read it with `ffprobe -count_frames -show_entries stream=width,height,nb_read_frames <file>` and check the length against `seconds=` in the `recording finished` line: a pause does not add to it.
- **Film GIF recording and conversion.** `CORNERMARK_GIF_FILM=<folder> swift run HarnessShell` films R7 and X8 from the real control bar, Quick Access cards and History, and plays each GIF back at its own delays. Add `CORNERMARK_INSTANCE_GIF=<file>` with a GIF copied out of an instance's `saved/` to play it at the end of R7. `CORNERMARK_OVERLAY_FILM` also writes `R7.mp4`: Record GIF and Option-Return in the overlay.
- **Clicks and keystrokes.** The pane cannot be clicked in a scripted instance, so start it from chosen settings: create the root first, write `<root>/settings.json` with `{"recording":{"clicks":{"isVisible":true},"keystrokes":{"isVisible":true,"keys":"all"}}}`, and launch with `CORNERMARK_VERIFY_ROOT=<root> $V/launch.sh`. A display link with `&style=video` then logs `recording input source=scripted clicks=true keys=all marksInPicture=true failure=none taps=0` and, after `record/stop`, `recording input finished clicks= keys= markedFrames= filledFrames=`. Without `style`, `project.json` holds the click and key tracks and the video has no marks. `taps=0` proves no event tap was made.
- **Film clicks and keystrokes.** `CORNERMARK_INPUT_FILM=<folder> swift run HarnessShell` films the real Recording pane and the files it recorded into `R12.mp4` to `R15.mp4`, keeps each raw recording beside them, and writes the whole pane as `R12-pane-light.png` and `R12-pane-dark.png`. `R13-recorded.mp4` and `R15-recorded.mp4` have the pointer off, so only the ring or the badge changes the picture, for timing.
- **Sound.** Seed the settings before launch: `{"recording":{"audio":{"microphone":true,"mono":true,"systemAudio":true}}}` in `<root>/settings.json`. `"microphoneID":"scripted.interface"` picks the scripted two-input interface, whose voice is on the left only. A recording logs `recording audio microphone=true device= mono= system= source=scripted ... realMicrophoneAccess= devicesOpened=0 accessRequests=0` and, after `record/stop`, `recording audio finished microphone=... seconds= channels= rate= filled= ... videoSeconds=`. Both `devicesOpened` and `accessRequests` must stay 0. The scripted microphone is silent from 4 to 9 s of every 12 on the recording clock, so a long take logs `recording microphone silent` and `recording microphone sound again`. Read the files with `ffprobe -show_entries stream=codec_type,codec_name,channels,duration`. An M4A's stream duration there is 44 ms longer than the video, the AAC encoder delay its edit list trims. Draw a waveform with `ffmpeg -i <file> -filter_complex showwavespic=s=1800x260:split_channels=1 -frames:v 1 <png>`. Never play a file.
- **Film the Audio pane.** With `<root>/test-stage.json` holding `{"stage":"audio","tour":true}`, `record/test-window` shows a 960x600 window with the real Audio pane and a copy of the control bar that follows the recording. With `tour`, the pane's own controls are clicked 2 to 13 s after the recording starts. Record it with `record window=<id>&style=video` while the screen is unlocked. Set `"showCursor":false`, so the pointer stays out of the picture.
- **Plain video.** Add `&style=video` to a display link. Both log lines say `style=video`, and `<root>/saved/` gets one `Cornermark Recording <date>.mp4` file and no project folder. The synthetic display has no real pointer, so this proves the file and the style, not the pointer in the picture.
- **Check the project.** The folder holds `screen.mp4` and `project.json` and nothing else. `project.json` has `source` (video name, pixel and point size, fps, duration), `events.pointer` (samples with `t` in seconds from the first frame and `x`, `y` in points from the top-left of the filmed area), and `edits.cursor` (`isVisible`, `scale`). A scripted instance replays a built-in pointer path, so `pointerSamples=` in the `recording finished` line is not zero. Hash `screen.mp4` with `shasum -a 256` before and after any rendering to show that edits never touch it.
- **Render the pointer.** The video editor's Export draws the stored project through `frameState` into a new MP4 and never writes `screen.mp4`. See [Video editor](video-editor.md) for driving it.
- **Check the file.** Run `ffprobe -count_frames -select_streams v -show_entries stream=codec_name,width,height,nb_read_frames,duration <file>`. Extract frames with `ffmpeg -ss <t> -i <file> -frames:v 1 <png>` and look at them. Only the synthetic scene may appear: dark background, a sweeping bar, a clock, and four colored corners (red top left, green top right, blue bottom left, yellow bottom right). A display recording also shows the fake Finder window and three fake desktop icons. The fake banner is hidden by default.
- **Focus.** `link.sh` and `watch.sh` hold a recording to this rule: the instance's only on-screen window is the test window, the instance is never frontmost, and the frontmost app never changes. A display recording shows no window of the instance at all.
- **Check the result.** After `record/stop` the log has `recording listed record=<id> format=video|project seconds=<s> card=true`. `<root>/History/index.json` has a record whose `video` holds `format`, `duration`, and `location`, the file or folder in `<root>/saved`, and the record's folder holds only `image.png`, the first frame. A display recording with `style=video` draws the scripted pointer into the picture, because the default Show cursor setting is on.
- **Film the results.** `CORNERMARK_RESULTS_FILM=<folder> swift run HarnessShell` films the real Recording pane, Quick Access cards, and History offscreen over the synthetic desktop into `R8.mp4`, `R16.mp4`, and `R27.mp4`. Each film shows frames of the files it recorded and what they measure.
- **Pause and restart.** During a display recording, run `$V/link.sh record/pause`, then `record/resume` or `record/restart`. The log has `recording paused seconds=`, `recording resumed`, and `recording restarted discarded=`. `record/discard` ends it with `recording discarded seconds=`, and `<root>/saved/` and History gain nothing. The `recording finished` line counts `pauses=`, and the file has no gap.
- **Recover after a crash.** Start a display recording, wait a few seconds, and stop the instance with `kill -9` on the PID that `launch.sh` recorded, after checking its binary. `<root>/unfinished/` keeps one journal file and the video plays to its last whole second. Relaunch on the same root with `CORNERMARK_VERIFY_ROOT=<root> $V/launch.sh`. The log has `recording recovered location=... seconds=...` and `hud Recovered a recording that was cut off`, the journal is empty, the folder has `project.json` again, and History lists it. Never kill any other process.
- **Render the panel, help and bar.** `CORNERMARK_PANEL_RENDERS=<folder> swift run HarnessShell` renders the real recording panel inside a 480 x 270 pt selection, the help window light and dark, and the control bar in each state into PNGs, and writes the options menu and every tooltip into `panel-renders.txt`.
- **Film the controls.** `CORNERMARK_CONTROLS_FILM=<folder> swift run HarnessShell` films the real control bar, countdown, dimming and menu bar button offscreen next to frames of the files they recorded. Add `CORNERMARK_RECOVERY_EVIDENCE=<folder>` with the copied cut-off folder, the killed instance's log and the relaunch's `evidence.sh` output to film the recovery too. Keep both folders under `$TMPDIR`.
- **Camera.** Write `<root>/settings.json` with `{"recording":{"camera":{"isVisible":true}}}` and launch with `CORNERMARK_VERIFY_ROOT=<root> $V/launch.sh`. A display link logs `recording camera wanted=true source=scripted access=allowed inPicture=<true for video and gif> failure=none requests=0 sessions=0`. During it, `$V/link.sh record/camera "shape=square&corner=topRight"` and `$V/link.sh record/camera` log `camera changed ... fullScreen=`. After `record/stop`, `recording camera finished pictures= filled= file=camera.mp4|none fullScreenSpans=` follows. In a project, `ffprobe -count_frames` gives `screen.mp4` and `camera.mp4` the same frame count and length. `edit-recording <folder> export` draws the camera into the export from the project. tccd shows no camera service.
- **Keep the proof.** Run `$V/evidence.sh <name>` before `stop.sh`. It copies `<root>/saved` too.
- **Everything else.** Run `swift run HarnessCapture` (sections `recording engine`, `stream geometry`, `recording settings reach the recorder`, `pause and resume`, `what a display recording leaves out`, `clicks and keys`, `live input boundary`) and `swift run HarnessShell` (sections `recording panel sources`, `recording panel options`, `recording panel help`, `delete`, `Settings shows what the recording panel chose`, `a source wanted in Settings but not allowed`, `recording panel sources in a scripted instance`, `recording settings model`, `Recording settings pane`, `finished recordings in Quick Access`, `recordings in History`, `recording links`, `recording policy of an isolated instance`, `recording flow`, `recording in a scripted instance`, `recording controls`, `countdown`, `restart`, `recovery after a crash`, `GIF recording`, `GIF from a finished recording`, `GIF recovery after a crash`, `clicks and keystrokes settings`, `clicks and keystrokes while recording`, `clicks and keystrokes without Input Monitoring`, `input source of an isolated instance`, `audio settings model`, `Audio settings pane`, `microphone and system sound while recording`, `export keeps the sound`, `a silent microphone while recording`, `sound of an isolated instance`) and `swift run HarnessCapture` (sections `GIF conversion` and `sound beside the video`, which prints `SYNC` lines with the click-to-flash offsets).

## Gotchas

- A locked screen composes no windows. A window recording then ends after under a second, with a handful of frames. `link.sh` refuses `record window=` while `screen_locked` holds. The synthetic display (`display=1`) still records, because it is drawn in the app.
- The `recording started` line has `clock=`, the host clock when the recorder came up. `firstFrame=` in the `recording finished` line is on the same clock, so the two differ by the start-up delay only.

- `link.sh record` refuses a window that is not the test window, and a display link with anything but `display=1` and whole-number area values. Never work around it. A display link in a scripted instance never builds a content filter on a real display. The harness check `recording policy of an isolated instance` proves that.
- The test window sits in the bottom-left corner of the main display, behind every other window, and may show when the desktop is exposed. It holds no real content. `record/stop` closes it.
- A window parked beyond the last display is captured too, but arrives unevenly: 7% of the frames at 60 fps were missing. The test window stays on screen for that reason.
- A scripted instance runs a debug build. The dropped-frame number is for a 480x270 window on a 120 Hz display.
- `record/stop` with nothing recording logs `recording refused`, and `link.sh` fails on it. Run it only after a start.
- Never send a scripted instance anything that would make it listen to real input. Its input source is the script, and `taps=` in the `recording input` line stays 0.
- If tccd logs a dialog, stop, run `stop.sh`, and report it. Never trigger the microphone or the camera.
