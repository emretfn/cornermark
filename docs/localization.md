# Localization

Cornermark's interface runs in 40 languages. English lives in the code. Every other language lives in `Localization/<code>.json`. `swift run L10nCheck` proves the two agree.

## Writing a string

Import `CornermarkL10n` and wrap every string a person reads, including tooltips, accessibility labels, menu items, alerts and HUD messages.

```swift
tr("Save folder")
tr("Version {version}.", ["version": version])
trPlural(one: "{count} day", other: "{count} days", count: days)
let title = trKey("Capture Area")   // stored in a table, read later with title.text
```

- The English argument must be a one-line string literal. `L10nCheck` finds strings by reading the source, so `tr(variable)` and `"\(x)"` inside the literal are errors.
- Values go into named `{placeholders}`. A translation can put them in any order. `Int` and `Double` values are written with the current locale's digits and grouping.
- A count always goes through `trPlural`, never `count == 1 ? … : …`. Each language spells out the plural forms its CLDR rules need. Arabic, for example, needs six.
- Never derive an identifier from a translated string. Accessibility identifiers, defaults keys and file names stay English and stable.
- Dates and numbers shown to people use `L10n.locale`, for example `date.formatted(.dateTime.locale(L10n.locale))`. File names and machine formats keep `en_US_POSIX`.
- Keep text the user typed, file names and the capture itself untranslated.

## Changing language without a restart

`L10n.setLanguage(_:)` posts `L10n.didChange` on the main thread. Every window, panel and menu that shows text observes it and re-renders its strings in place, keeping its state: the selected pane, the scroll position, the open document, field contents, the selection.

The simplest correct way is usually to rebuild the content view from the same builder that made it, then restore state. Text that is computed at display time, such as a menu built when it opens, needs nothing.

## Right to left

Arabic, Hebrew and Persian mirror the interface. `NSApp.userInterfaceLayoutDirection` is fixed at launch, so direction is set per view.

- After building or rebuilding a view tree, call `view.applyLanguageDirection()`. Call it again on subviews added later, such as cells and cards. Leading and trailing constraints and `NSStackView` order then mirror on their own.
- A view that shows a picture of something (a screenshot, the canvas, a video frame, a thumbnail's image) adopts `KeepsLeftToRight`. It and its subviews are never mirrored.
- Frame-based `layout()` computes left-to-right frames and writes them through `mirrored(_:)`.
- Custom `draw(_:)` that places things by side (a hairline on the right edge, a label after an icon) checks `isRightToLeft`.
- A symbol that points in reading order (chevrons, back and forward, undo and redo) goes through `Glyph.directional(_:)`. Symbols about the picture itself (rotate, flip, crop handles, an arrow tool) stay as they are.
- Text fields keep `.natural` alignment rather than `.left`, so they follow the language.

## Files

- `Localization/en.json` is generated from the code by `swift run L10nCheck --write`. Do not edit it.
- `Localization/<code>.json` holds one translation. Keys are the English strings. A plural is an object keyed by CLDR category.
- `Sources/CornermarkL10n/Catalogs/` embeds the catalogs in the binary. It is generated by `--write`. Do not edit it.

## Adding or changing a string

1. Write or change the `tr` call.
2. Run `swift run L10nCheck --write`. It rewrites `en.json` and lists the keys every language is now missing or no longer uses.
3. Translate those keys in each `Localization/<code>.json` from the English, then run `--write` again.
4. `swift run L10nCheck` must print `RESULT ok`.

## Checking a window in a harness

`L10n.setPseudoLanguage(.ar) { "‹\($0)›" }` switches to a right-to-left language and wraps every string that goes through `tr`. A harness check walks the window's views after the switch and asserts that each visible label, button title, tooltip and accessibility label is wrapped, so a hard-coded string or a window that did not re-render fails. `L10n.setLanguage(.en)` switches back. The harnesses never read the Mac's language: `L10n` starts in English, and the harness environment reports English as the preferred language.
